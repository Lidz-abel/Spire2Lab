SpireLab：整体框架与第一阶段建设规划
规划日期：2026-10-19

目标与约束
建立可搜索、可分层决策、可高效训练的自主强化学习系统，并在真实《杀戮尖塔 2》中评估。
第一阶段交付有限范围内可信、可观察、可复现的环境；之后扩展策略、内容和训练规模。
Linux 承担模拟、搜索、策略推理、训练、日志与面板服务；低配置 Windows 运行 Steam
游戏、轻量状态/动作桥接及后续画面采集。Windows 不承担批量采样或训练。
当前采用结构化玩家可见观测和实验面板；后续接入原版画面。

架构
  随机/启发式/学习策略；后续：上层目标 -> 战斗规划 -> 单步执行
                         |
                   实验运行控制器
                         |
              统一 Observation / Action / StepResult
                  /                      \
  Linux 原生模拟器适配器             Windows 原版适配器
  多进程环境、搜索分支               SSH -> Mod -> 原版游戏
                  \                      /
               追加式轨迹、版本信息、验证报告
                         |
                 实时面板与逐步回放
                         |
        后续：按实验/决策编号关联的原版截图或视频帧

推荐复用的基础
1. evangambit/sts2：C# NativeAOT 规则引擎，通过 ctypes 进入 Python，再封装 Gymnasium。
   当前固定 37e4264115546b6ac640d54aab3d7e2ac6983d2d，声明目标 v0.107.1。
   https://github.com/evangambit/sts2/blob/37e4264115546b6ac640d54aab3d7e2ac6983d2d/README.md
2. evangambit/STS2MCP：原版 Mod 的状态读取和动作接口，借鉴真实游戏采集方法。
   当前固定 18bc23be210bbe804ae4471dfd2cb33bd481e247；实际兼容须用本机 DLL 编译验证。
   https://github.com/evangambit/STS2MCP/blob/18bc23be210bbe804ae4471dfd2cb33bd481e247/README.md
3. Gymnasium：reset/step、terminated/truncated、随机种子和训练封装。
   https://gymnasium.farama.org/api/env/
以上项目提供可复用实现和方法，不能替代本项目的实机验收。

第一阶段必须固定的六条接口边界
1. 观测与隐藏状态
   策略只获得玩家可见信息、历史记录和合法动作。未知抽牌顺序、随机数内部状态、
   未公开敌人未来动作不进入策略输入或普通面板。抽牌堆可见组成与未知顺序分别处理。
   调试和一致性校验需要的完整状态独立存储；字段缺失明确标记，不能填零冒充实测值。
   后续学习策略使用相同信息边界；评价策略时不提供比真实玩家更多的信息。
2. 语义动作与训练编码
   核心动作表达为“出哪张牌、对哪个目标、结束回合”，携带 decision_id 与请求编号。
   当前决策中的实体引用必须唯一；跨决策持久身份尚未保证，不据此关联同名卡。
   动作整数编码和神经网络张量属于可替换训练封装。扩充卡牌/阶段时升级编码版本，
   不让面板、原版适配和轨迹格式依赖固定数组位置；超出容量明确报错。
3. 决策边界与执行结果
   一步是一项玩家决策，持续到游戏完成结算并进入下一个可决策状态或终局。
   动画、轮询、网络重试不产生训练步。分开记录已建议、已提交、已确认与结果未知。
   动作请求去重；响应丢失先读取确认，禁止盲目重发。异常轨迹保留未知结果，
   不当作失败奖励或正常训练样本。人工接管单独标记，允许过滤。
4. 实际环境与搜索分支
   两种后端共用观察/动作协议，按能力声明 reset、精确快照、分支和画面支持。
   原版暂不具备任意 reset/clone；第一阶段需补齐可重复的场景初始化并验证。
   精确 snapshot/restore 服务恢复、回归测试与分支隔离。
   搜索另行使用与可见历史一致的未知状态采样，不能使用实际隐藏牌序作预知。
   当前 sample_world 是后续搜索的起点，完整历史条件化的信念模型仍需后续设计验证。
   模拟分支具有独立编号和父分支引用，不发送动作给实机，不计入真实执行轨迹。
5. 决策记录、层级与训练样本
   决策记录包含候选动作、分数含义、所选动作、策略版本、耗时和可核查的依据。
   后续追加搜索预算、访问次数/价值估计、模型检查点、上层目标及父决策编号。
   当前启发式评分不包装成概率；后续解释来自算法实际计算结果。
   原子动作轨迹作为基础事实，上层目标覆盖的多个动作另记持续步数、累计回报和
   终止条件，为跨步折扣与分层训练保留依据。
   奖励是带版本的转换规则，HP/伤害/资源变化等事实独立保存，便于重算奖励。
6. 展示、原版画面与规则
   面板只渲染统一观测和决策记录，游戏规则由原生引擎或原版游戏执行。
   卡牌、敌人、意图、数值、动作目标和决策时点必须能与原版对应。
   同一原版对局的观测、动作、截图通过 run_id/decision_id/frame_id/时间戳关联。
   后续先采集稳定决策边界的截图，再按 Windows 性能增加低帧率视频。
   原版画面展示与纯视觉智能体是两个独立里程碑；后者需要增加感知模块和独立评测。
   模拟器分支无法自动生成可信的原版截图；面板必须明确标注后端和数据来源。

第一阶段范围
铁甲战士，A0，5 张 Strike、4 张 Defend、1 张 Bash，Burning Blood，无药水，
80/80 HP、99 金币、第 2 层，三个遭遇：nibbits-weak、slimes-weak、sludge-spinner。
基线为随机合法动作和可解释启发式，完成单场战斗；暂不开展 RL 训练。
当前 config/phase1.json 定义 10 个开发种子和 10 个保留评测种子。
“2026-06-19 默认公开版本”是用户描述；最终必须采集 Steam Build ID、实际游戏
版本和 DLL 哈希。工作区的 v0.107.1 不是用户 Windows 已安装版本的证明。

建设顺序与交付
步骤 1：冻结实验版本和范围
  交付游戏/Mod/模拟器/协议/编码版本清单及固定场景配置。
  首先核对 Windows 真实版本；若与当前引擎目标不符，明确调整兼容方案并重做验证。
步骤 2：打通最小实机闭环
  Windows 采集版本与编译引用 -> 建立 SSH 隧道 -> Linux 编译 Mod -> Windows 安装。
  读取一个稳定战斗状态，面板显示，提交一项动作，等结算，核对游戏与记录结果。
  再执行完整战斗，检查暂停、断线确认和人工接管；保留全部原始证据。
步骤 3：完成可重复初始化和随机性对齐
  建立受控场景准备工具；记录场景是原生流程产生还是调试接口布置。
  比较相同初态和相同动作序列的每一步。分别检查公开初态、牌堆顺序及 RNG 来源。
  相同数字种子不足以证明两个引擎随机过程一致；不得用反复搜种子或修改后续状态
  来掩盖差异。无法对齐时报告失败，并修复初始化/RNG 映射后重新验收。
步骤 4：形成有限范围参考集
  固定 3 遭遇 × 10 开发种子 × 2 策略 = 60 条独立完整实机参考战斗。
  另外补充正常策略覆盖不到的边界探针，包括失败结局。
  检查出牌、结束回合、跨回合、状态牌意图/入堆、能力效果、敌人死亡、胜负。
  每条原版轨迹匹配独立模拟器重执行，缺失、未决、合成数据均不得计为通过。
  对比范围只涵盖独立实测字段；借用模拟器规则表得到的值不充当独立证据。
步骤 5：验收面板、复现和训练兼容
  单步、自动、暂停、人工动作、决策依据、实时状态、回放、记录导出可用。
  同一构建/初态/种子/动作可重放；搜索分支互不影响；合法动作与隐藏信息检查通过。
  Gymnasium 契约、终止/截断、多进程采样与资源释放通过验证。
  独立测量无面板采样吞吐、决策延迟和内存；不提前承诺 steps/s 或胜率。

第一阶段完成条件
全部适配器/协议/面板检查通过；60 条实机参考及边界覆盖完成；每一步可追溯。
游戏版本、规则源码、Mod、模拟器二进制或证据变化后，已有结论失效并重新核验。
结论应写“某版本、这些场景、这些字段通过参考集验证”，不扩大为全游戏完全一致。
界面可运行、模拟器自测通过或接口合成测试通过，单独都不足以完成第一阶段。

后续路线与第一阶段的衔接
阶段 2：单场战斗搜索
  在可见信息边界内比较启发式、有限深度搜索与适合不完全信息的树搜索。
  统一墙钟预算/节点预算，报告胜率、剩余 HP、延迟和计算量，验证搜索确有收益。
  复用模拟器分支、语义动作、轨迹和面板；不直接假定完整信息 AlphaZero 可用。
阶段 3：高效学习与搜索结合
  先建立一个可靠的带动作掩码学习基线，再评估行为克隆、搜索数据训练、价值引导
  搜索等路线。采用进程隔离采样和批量推理；算法选型由测量决定。
  同时比较样本量、训练时间、算力成本和保留种子表现，保存模型/数据版本。
阶段 4：分层与整局扩展
  按“更多战斗内容 -> 单幕流程 -> 更完整整局”扩充并逐批实机对照。
  上层做路线、牌组和资源决策；中层做战斗目标/计划；下层执行原子动作。
  每层使用明确的目标、持续步数和终止条件；数据结构复用，新增内容仍需要开发。
阶段 5：实机部署与原版画面
  可靠实机桥接后即可并行加入原版截图/视频展示，不必等待全部训练阶段结束。
  用相同策略接口驱动原版，测量模拟器到实机性能差距；可选进一步研究纯视觉观测。
